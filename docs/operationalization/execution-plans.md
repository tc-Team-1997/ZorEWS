# ZorEWS — Operationalization Execution Plans

**Last updated:** 2026-05-21
**Authoritative parent:** [`docs/production-operationalization-roadmap.md`](../production-operationalization-roadmap.md)
**Companion artefacts:** [dependency-matrix.md](dependency-matrix.md) · [readiness-checklists.md](readiness-checklists.md) · [go-live-gating.md](go-live-gating.md)

> Decomposes each of the 9 operationalization tracks from the roadmap into engineering-phase units that a named owner can pick up and execute. Every phase row carries: ID · owner · duration · prerequisites · deliverables · validation gate · rollback · risks. **Implementation-ready.** No new feature work — runtime wiring + IaC + hardening only.

## Conventions

- **Phase ID** = `T<track>-P<phase>` (e.g. `T2-P3` = data-plane Aurora migrations).
- **Owner** = role from `docs/raci.md` (`SRE`, `INT`, `DATA`, `CISO`, `RIT`, `UI`, `ORCH`).
- **Duration** = wall-clock business days, assuming the owner is single-threaded on the phase.
- **Prerequisites** = phases that must reach `validation gate green` first.
- **Validation gate** = testable assertion. If it fails, the phase is NOT done — rollback engages.
- **Rollback** = the concrete action that reverses the phase (Terraform destroy, ArgoCD revert, IAM detach, etc.).
- **Risk** = the specific failure mode with the most production impact, plus its mitigation.

Phase IDs are referenced by name in `dependency-matrix.md`, `readiness-checklists.md`, and `go-live-gating.md`. Do NOT rename phase IDs once shipped — downstream docs use them as anchors.
